## Notes on the numbers

- **Terminal rows (tty)** measure first content paint on a fresh pty — the
  closest terminal analogue of a GUI window showing content. The `quit` rows
  (hyperfine) measure open-and-quit, which includes process spawn + teardown
  and excludes painting (the issue's proposed metric, kept for reference).
- **GUI cold** includes app process spawn (LaunchServices handoff, dyld,
  first window). **GUI warm** opens a file into an already-running instance —
  the comparison that most directly reflects editor open-path quality.
- OpenEdit numbers come from the release build of the perf branch
  (`build/OpenEdit.app`), with the progressive-highlight path for large
  documents described in ARCHITECTURE.md §5.4.
- VS Code runs in an isolated profile without extensions/trust
  dialogs/large-file confirmation; TextEdit, Zed, Sublime, CodeEdit, Nova,
  BBEdit ran with defaults after first-run dismissal via `axpress`.
- Machine: Apple M4 Pro (12-core), 24 GB, macOS 27.0.1. Runs are serial; no
  concurrent CPU load during timed runs. Page cache is warm after the first
  run of each file (cold *disk* is not what is measured; cold *process* is).
